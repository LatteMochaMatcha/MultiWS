# 英文、日文版：写法和术语表

工坊界面做成中、英、日三语，一个包里带三种，右上角（主题按钮左边）选语言。分支 `feature/i18n`，worktree `F:\Downloads\多tool-i18n`。

## 怎么做的

- `src/i18n/index.ts`：`t('中文原文', { 变量 })` 返回当前语言的文字。**键就是中文原文**，英文、日文放在 `src/i18n/en/*.json`、`src/i18n/ja/*.json`（`{ "中文原文": "译文" }`），几个 JSON 合在一起查，查不到就显示中文。
- 语言在页面载入时定（`?lang=en` > 存过的选择 > 浏览器语言，都不是中日就英文）；换语言是存起来、整页重新载入。所以**模块顶层的常量里也能直接写 `t()`**。Node 里（测试、tools 脚本）一律是中文。网格线程靠线程名 `lang=xx` 知道语言。
- `index.html` 里写死的中文不用改：页面载入时 `translatePage()` 按原文查，换文字节点和 `title`、`placeholder`、`aria-label`、`alt`。段落里夹着 `<code>` 之类标记的，元素上加 `data-i18n-html`，整段 innerHTML 当一个键。`translate="no"` 的不动。
- `node tools/i18n-keys.mjs`：抽出所有键，报缺多少译文、占位符对不对；`--dump` 把键连同出处写到 `.harness-tmp/i18n/keys.json`、`missing-en.json`、`missing-ja.json`；`--file src/xx.ts` 只看一个文件。
- `tests/i18n.test.ts`：每个键都要有英文、日文，占位符要对得上，英文里不能有汉字、假名。

## 包字符串的规矩（改 .ts 时）

1. **只包给用户看的文字**：按钮、标签、提示、状态栏、弹窗、`title` / `aria-label`、抛出后会显示在界面上的 `Error` 信息。**不包**：`console.*` 的开发日志、注释、拿来当键 / 拿来比较 / 拿来解析的中文（例如解析器的词表、`describeSpec` 输出的规范描述）、写进导出文件给别的软件读的内容（文件名可以保持英文的就别动）。拿不准就看这个字符串最后流到哪里。
2. `t()` 的第一个参数**必须是一个字面量**（抽键脚本只认字面量）。拼起来的 `'a' + 'b'` 合成一个；模板字符串里的 `${x}` 改成占位符：
   ```ts
   setStatus(`已导出 ${fileName}（${sizeText(blob.size)}）`)
   // 改成
   setStatus(t('已导出 {file}（{size}）', { file: fileName, size: sizeText(blob.size) }))
   ```
   占位符名用英文小写单词（`{n}`、`{name}`、`{file}`）。一句话尽量整句做一个键，别切成碎片（不然英文、日文语序没法调）。句子里夹的可选片段（`${pose ? '摆好的姿势，' : ''}`）可以单独 `t()` 再当变量填进去。
3. 中文原文**一个字都别改**（包括标点、空格）——键就是它；只有改成占位符的那部分变。
4. 表里的中文值既要显示、又要拿来当键或比较时：定义处用 `tk('…')`（原样返回，只登记成键），显示的地方再 `t(变量)`。`t(变量)` 抽键脚本看不到，所以这些值必须在别处用 `tk()` 或 `t()` 字面量登记过。
5. 同一句中文在不同地方意思不同、要译成不同的话（「头 {n}」既是「第 2 个头」又是「2 个头」）：其中一处的键后面加 `@@语境`，如 `t('头 {n}@@数量', { n })`；中文显示时 `@@` 及后面的字去掉，英文、日文按整个键查。
6. 数量拼接：中文 `${n} 条腿` → `t('{n} 条腿', { n })`；英文译文里分单复数写 `{n:leg|legs}`（`n` 是 1 时取前一个），如 `"{n} {n:leg|legs}"`。日文不用。
7. 改完跑 `npx tsc --noEmit` 和 `node tools/i18n-keys.mjs --file <你的文件>`（不能有「!」开头的毛病）；动了被测试覆盖的文件就跑对应的 `npx vitest run tests/xxx.test.ts`。测试里语言是中文，原来的断言应该照样过。

## 翻译的规矩（写 JSON 时）

- 每个代理只写分给自己的 JSON 文件（`src/i18n/en/<名字>.json` 和 `src/i18n/ja/<名字>.json` 成对），别动别人的。
- JSON 的键原样复制中文原文（从 `.harness-tmp/i18n/keys.json` 或 `--dump` 的输出里拿，别手打）。占位符原样保留在译文里；`{n:单|复}` 只在英文里用。
- **英文**：界面口吻简洁，按钮、标签用 Title Case 以外的「句首大写」（`Export GLB`、`Show bones`）；整句提示用完整句子。别加原文没有的意思。中文里引用界面上别的按钮、栏目时用的「…」，英文用双引号 "…"，引号里要写**那个按钮的英文译名**（去 `src/i18n/en/*.json` 里查已有的译法）。
- **日文**：按钮、标签用名词或简短的动词形（「書き出し」「元に戻す」），整句提示用です・ます体。引用界面上的按钮用「…」，里面写那个按钮的日文译名。片假名外来词照日本 3D 软件（Blender 日文版、VRoid Studio）的常见说法。
- 中文的「·」分隔、「（…）」括号：英文换成半角 `·`、`(…)`，日文保留全角「（…）」。
- 长度：英文通常比中文长一倍以上，面板很窄（约 320 px）。按钮、分段选择、标签尽量短，能用常见缩写就用（`L` / `R`、`Fwd`），长解释放到提示（title）或说明段落里。
- 人名、软件名、格式名（Blender、VRoid、VRM、GLB、OBJ、STL、Tripo、Quaternius、Mixamo）照原样。
