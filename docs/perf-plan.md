- **烤胸分给几个线程**（`src/sdf/grids.ts`、`parallel.ts`）：融合前先「试编译」一遍场，记下这次要烤、还没烤过的胸，按层（沿 z）分段，分给帮手和自己一起烤，收下以后再正式编译。

|---|---|
| 松手后出预览 | 1.64 s → 0.52 s |
| 松手后出精细 | 6.36 s → 1.66 s |
| 进摆姿势（到精细的带权重网格） | 6.48 s → 1.3–1.9 s |

白模没有烤胸这一步，几项都和原来差不多。这几轮量的时候另外两个会话在同一台机器上开着页面和第二个开发服务器（CPU 常在五成上下），数字上下抖一两成。

做了什么，和计划不一样的地方：

- **2a 烤好的胸**（`src/sdf/grids.ts`、`src/sdf/parallel.ts`）：
  - 量出来最大的毛病不是「每个线程各烤一遍」，是**缓存只按个数留 12 份**：你这副身体 8 个胸 × 粗、预览、精细三档 = 24 份，轮着算时互相挤掉，拖手臂（胸根本没变）每次精细网格也要重烤（单线程约 2 秒）。改成按字节留（每个线程最多 96 MB，你这副三档全留着是 30 MB）。
  - 网格 Worker 烤好的胸随这个任务的头一份活交给帮手线程（每个帮手只给一次），帮手照用，不再自己烤。算权重时各部件的场按 4 mm 烤，和精细那档是同一份，也一起交过去。
  - 没做的：把「烤」本身分给几个线程一起算。胸的样子变了（拖胸、拖胸围这类滑块）以后第一次精细网格还是要在网格 Worker 里单线程烤两秒左右。
- **2b 表面校正分给帮手**（`src/sdf/surfaceQuality.ts`、`fuse.ts`、`job.ts`、`parallel.ts`）：收尾那段里表面校正占四分之三。拆成三步：哪些顶点不动、各顶点挪回表面（按 4096 个顶点一份分给帮手）、挪坏了的面退回去重算法线；带权重的那条路（进摆姿势）也一样。精细任务 1.09 s → 0.71 s。
- **2c 精细网格晚一点算**：没照计划一律等 1.5 s。精细网格现在只要 0.7 s 左右，再一律等 1.5 s，每次松手看到精细网格都要多等 1.25 s。改成照刚到的那张预览算了多久来等（0.25–1.5 s 之间）：素体约 0.3 s，胸换了样子要重烤的时候多等。

核对：

- `bench-fusion.mjs --compare`：12 种身体 × 两档精度，逐顶点一样（拓扑相同、坐标差 0）。
- 浏览器里新旧两份代码算你这副身体：造型的精细网格、进摆姿势后带权重的网格，散列值都一样（素体 `fe2a8a40`、`c674fde3`，白模 `7d03175e`、`aef90817`）。这条路上是真的帮手线程、跨线程交过去的胸、分段的表面校正。
- `tests/parallel.test.ts` 加了二次元素体静止、带权重两种（表面校正分开算、胸交给帮手），`tests/bakedChests.test.ts` 锁住三档都留得住。全部 1379 项测试通过。

还没解决的（不在计划里，量的时候看到的）：

- 摆姿势松手后照姿势重新融合的那张，第一次要 5 秒上下：那是另一个网格 Worker，第一次要自己烤胸（摆姿势用的里侧胸是去掉切口的另一份，别的 Worker 烤好的也用不上），
  还可能排在一个作废了、但正在编译或收尾停不下来的精细任务后面。之后几次就快了。照姿势融合的场本身也贵（单线程预览 3.9 s、精细 19 s）。
  办法：把「烤」分给几个线程一起算；作废的任务在编译、收尾时也能停。

## 3a、3b 做完以后（2026-11-02）

量法：`node tools/bench-drag.mjs --spec .harness-tmp/perf/user-spec.json --drag pose`（够不着：手画 15 cm 的圈），加 `--bend` 是弯肘（手往肩膀收一半再伸回去）。
「改之前」同样是在 5181 端口开 HEAD 的代码量的。

| 摆姿势拖手，每次拖动主线程 p50 | 素体 | 白模 | 成品角色 |
|---|---|---|---|
| 弯肘（够得着，只有这条手臂动） | 18.1 → 2.0 ms | 15.9 → 2.1 ms | 6.3 → 2.1 ms |
| 够不着、身体跟过去（全身都动） | 19.6 → 7.7 ms | 16.0 → 5.3 ms | 6.4 → 3.2 ms |
| 帧率（弯肘 / 够不着） | 56 → 165 / 50 → 120 | 59 → 165 / 60 → 133 | 133 → 165 / 125 → 165 |

做了什么：

- **3a**（`src/view/posedMeshes.ts`、`src/character/pose.ts`）：记下上一次用的骨骼矩阵，只重算矩阵变了的骨骼带着的顶点；
  大半骨骼都动了（身体跟过去）就直接全部重算，不一个个顶点地查。成品角色的表情是加在静止样子上的：表情变了的顶点也重算。
- **3b**：拖着的时候（`main.ts` 的 `grab` 不为空）包围盒只放大到框得住这次挪过的顶点，包围球照包围盒取；松手以后同步那一次照常算准的。
- **顺手的一处**：每个顶点上归一化用的 `Math.hypot` 换成 `Math.sqrt(x*x + …)`。V8 里 `Math.hypot` 比开平方慢好几倍，
  7.5 万个顶点的对偶四元数蒙皮从 15.4 ms 降到 5.3 ms。全身都动时主要靠这一处；导出摆好姿势的模型用的是同一个函数，也跟着快。

量的时候发现：你这个姿势手臂几乎伸直，往哪边拖一小段都够不着，身体就跟过去，九成以上的骨骼都在动。所以「只重算一部分」只在弯肘、往身体这边拖的时候省得多；
往外拖时省下来的主要是 `Math.hypot` 那一处和包围盒。

核对：

- 只重算一部分的结果和从头全部重算的逐值一样：`tests/posedMeshes.test.ts`（线性、对偶两种混法、表情、包围盒），
  真实网格上三种样式 × 弯肘 / 够不着 × 两只手和一只脚，拖完以后放回静止再全部重算比，差 0 个值。
- 换成 `Math.sqrt` 以后，摆好姿势的网格和旧代码逐值一样：三种样式在新旧两个服务器上摆同一个姿势，顶点、法线的散列值相同。
- 全部 1373 项测试通过。

还剩：全身都动时素体每次 7.7 ms，其中蒙皮大约 5 ms。再要快就是 3c（挪到显卡上）。进摆姿势要等的那几秒（素体 7–9 s）是第 2 期的事。

- 松手后的两项几次量下来上下差一成左右，在误差里：给顶点标部件大约占每次融合的 5–7%（素体预览 60 ms、精细 170 ms，白模预览 20 ms）。

  对照量过：不挪、挪但不传给显卡、照常挪，帧时间都是 12–13 ms。
- 松手以后的网格和改之前逐顶点一样：`bench-fusion.mjs --compare` 12 种身体 × 两档精度，拓扑相同、坐标差 0。全部 1352 项测试通过。

做了什么：

- **1a**（`src/view/fusedModel.ts`）：后台回来的网格只要比屏幕上那张新（按发出去的先后），就换上；停下来以后的预览、精细照旧只认最新参数。
- **1b**：拖动中的格子：预览那档 110 ms 内算得完就直接出预览，否则 0.02（和原来一样；照各档用时挑的那张表用不上，见最上面那节）。
  原计划还有 0.025 那档：素体只快两成，脸和胸糊成一团，去掉了。所以素体拖着时每秒 5 次，没到计划的 8–10 次。
- **1c**（`src/sdf/labels.ts`，新文件）：网格 Worker 算网格时顺便给每个顶点标出属于哪个部件（离哪个部件自己的表面最近；接上去的手、脚照自带的骨骼认），
  主线程每次参数变了，照各部件从「算这张时」到「现在」的变换把顶点搬过去。
  - 只在关节附近（离关节 12 cm 以内、部件和它的父部件之间）渐变。一开始是「离谁都近就渐变」：你这副胸很大，垂着的手臂贴着胸，一抬手前臂就被胸拖住，扯出一片帘子，改了。
  - 只在部件还是那几个、只是位置角度大小长短变了的时候挪；换样式、加减部件不挪，等新网格。
  - 不只操纵杆，拖「手臂长短」这类滑块、在数字框里改微调也一样跟手。
- **第 0 期**：`tools/bench-drag.mjs`。Chrome 的用户目录放在系统临时目录里，不能放进项目：Chrome 往里写 html 文件，开发服务器看见了会让所有页面刷新。

## 量了什么、怎么量的

- 另开一个无界面的 Chrome（单独的用户目录，不碰你那一页、不碰你存的设定），载入你页面上现在这副身体（两个上半身、一个头、一对手臂、两对胸、一对腿，二次元素体，融合），再分别换成白模人台、成品角色。
- 用脚本模拟拖动：每一帧动一次，连拖 3 秒，记主线程每次拖动花多少、帧率、身体网格多久换一次、松手以后多久出预览 / 精细网格，同时录 CPU 火焰图。
- 融合本身另在 Node 里单线程量（同一副身体，各精度）。
- 本机：i7-14700HX、RTX 4070，插着电。**用电池时 CPU 那几项大约要乘 2–3。**

## 量出来的

### 造型：拖手臂的操纵杆（「手动微调」）

| | 二次元素体（你现在这副） | 白模人台 | 成品角色 |
|---|---|---|---|
| 主线程每次拖动 | 约 3 ms | 约 2 ms | 约 7.5 ms |
| 帧率 | 89 | 88 | 58 |
| **拖着的 3 秒里身体网格换了几次** | **0** | **0** | 每帧都跟（不融合） |
| 松手以后 | 粗网格 0.2 s → 预览 1.4 s → 精细 6.0 s | 预览 0.14 s → 精细 0.6 s | — |

主线程不忙，也没有超过 50 ms 的长任务，**卡是因为身体一直不动**：只有半透明的高亮跟着操纵杆走，身体要等松手（或者停下来不动）才跳过去。

原因在 `src/view/fusedModel.ts:179`：每动一下参数就变一次（`wantKey`），后台算好的网格回来时一看参数已经不是最新的，就整张丢掉。后台算一张最快也要 70 ms（白模预览）/ 170 ms（素体粗网格），比一帧长得多，所以只要手一直在动，每一张都是过时的，一张都显示不出来。后台线程这期间一直满载，算的全是要扔的。

### 摆姿势：拖手

| | 二次元素体（7.5 万顶点） | 白模人台（8.2 万顶点） | 成品角色 |
|---|---|---|---|
| 主线程每次拖动 | 11 ms | 13.7 ms | 7 ms |
| 其中按权重搬顶点 | 7.8 ms | 10 ms | 4.7 ms |
| 其中重算包围盒、包围球 | 2.4 ms | 2.4 ms | 1.1 ms |
| 帧率 | 84 | 68 | 122 |
| 进摆姿势时「正在给网格配上骨骼」 | 你的页面 6 s（我这边 3 s） | 不到 1 s | — |

插着电还算跟手；用电池时每次拖动 25–40 ms，就只剩二三十帧。每动一下都把**所有**顶点搬一遍（`src/view/posedMeshes.ts:57`），拖一只手时其实只有手臂那一截的骨骼在动。

### 融合本身（Node 单线程，毫秒）

| 精度 | 二次元素体 | 白模人台 |
|---|---:|---:|
| 粗（0.02） | 231 | 63 |
| 预览（0.012） | 753 | 155 |
| 精细（0.0065） | 5116（第一次烤胸占 2256） | 637 |
| 预览 + 蒙皮权重（进摆姿势） | 4018 | 223 |

素体比白模慢 5–18 倍，火焰图里最费时的几样：

1. `grids.ts` 的 `one`（查采样格子）：求值时间的一半左右。
2. **烤胸**（`chestDist → bake`，`grids.ts:631`、`:830`）：每个胸型、每档格子大小第一次要烤，预览 0.7 s、精细 2.4 s；**每个线程各烤一遍**（网格线程 + 6 个帮手）。进摆姿势算权重时（`rig/skin.ts` 的 `planSkin → compilePartField`）按最细的 4 mm 烤，火焰图里这一项连带占了 4.2 s。
3. `refineSurface`（表面校正）：预览 0.4 s、精细 1.0 s，只在一个线程上算。
4. `fork.ts` 的 `map`（上半身分叉的逆变形）：0.3–1.2 s。

浏览器里预览反而要 1.2 s（Node 单线程 0.75 s）：烤胸、表面校正、缝合都只在一个线程上，多线程帮不上；后台线程也可能被排到能效核上（这一条是推测）。

### 不是问题的

- 造型时每次拖动的主线程开销（改设定、记撤销、存档、刷新面板、重新摆位）合计 3 ms 左右，不是这次卡的原因；放到第 4 期顺手收拾。
- 显卡画 15 万三角面加阴影，每帧 3–5 ms，够用。

## 分期

按「你感觉到的卡」排：先让身体跟手，再缩短松手后的等待，最后收拾零碎。

### 第 0 期：量具（半天）

- `tools/bench-drag.mjs`：照这次的办法，开一个单独的无界面 Chrome，载入指定设定，脚本拖操纵杆和圆点，打出上面那几张表的数。几种身体：你现在这副 × 三种样式，加上 `bench-fusion.mjs` 里的三头三对手、三个上半身。
- 以后每期前后各跑一遍，数写进本文件。

### 第 1 期：造型里拖着时身体跟手（最要紧）

改 `src/view/fusedModel.ts`、`src/main.ts`，不改融合算法。

- **1a 拖着的时候用最新算好的那张**：后台回来的网格只要比屏幕上那张新就换上，不再要求参数和最新的一模一样；「停下来以后换预览、换精细」照旧按最新参数。
  预计：拖着时身体每秒更新——白模 10–15 次、素体 4–5 次（现在是 0）。
- **1b 拖着时格子粗细跟着算得快慢走**：照上一张粗网格花了多久挑格子，让一张在 80 ms 左右出来（素体会更粗一些，松手后照旧换细的）。
  预计：素体拖着时每秒 8–10 次。
- **1c 选中部件就先「整块挪」**：选中一个部件时，后台给屏幕上那张网格的每个顶点标出「属于这个部件和它带着的部件（手臂带着手）」的程度，接缝附近渐变（照 `sdf/pick.ts`「离哪个部件最近」的办法；左右同调时对侧也标）。拖着的时候主线程只把这些顶点照操纵杆的位移 / 旋转 / 缩放搬过去（约 1–2 ms），每帧都跟；融合好的网格到了再换上。
  预计：手臂每帧都跟着操纵杆走；肩膀那里的融合圆角晚 0.2–1 s 补上（拖着时接缝是扯出来的样子，和摆姿势时一样）。

验收：bench-drag 里「拖着时网格换了几次」从 0 变成每秒几次（1a、1b），1c 做完后高亮和身体对得上；松手以后的网格和现在逐顶点一样（`bench-fusion.mjs --compare`）。

### 第 2 期：松手以后的等待（二次元素体）

改 `src/sdf/grids.ts`、`src/sdf/surfaceQuality.ts`、`src/sdf/parallel.ts`、`src/rig/skin.ts`。**`grids.ts` 归「胸部、上半身和多胯修复方向」会话管，要你点头才动。**

- **2a 胸只烤一次**：网格线程烤好，把格子数据交给帮手线程，不再每个线程各烤一遍；算权重时用同一份，不另按 4 mm 烤；烤好的按胸型留着，拖手臂、腿时不重烤。
- **2b 表面校正分给帮手**：按顶点分段，几个线程一起算（每个顶点互不相干，结果不变）。
- **2c 精细网格晚一点再算**：停下来 1.5 s 没再动才算精细的（现在是 0.25 s），连着改的时候后台不白忙。

预计：素体预览 1.4 s → 0.6 s 左右，精细 6 s → 2–3 s，进摆姿势 3–6 s → 1.5–2 s。
验收：同一副身体的预览、精细、导出网格逐顶点一样（`bench-fusion.mjs --compare`）；`tests/sdf.test.ts`、`parallel.test.ts`、`bust.test.ts`、`posedField.test.ts` 通过。

### 第 3 期：摆姿势拖动

改 `src/view/posedMeshes.ts`、`src/character/pose.ts`、`src/main.ts`。

- **3a 只搬动了的**：记下这一帧哪些骨骼的矩阵变了，四根骨骼都没变的顶点跳过（拖一只手时大约只剩两三成；「够不着身体跟过去」时才全身都搬）。
- **3b 拖着时不重算包围盒**：拖动中用骨骼位置估一个够大的包围球，松手再精确算一次。
- **3c（可选，大一些）搬顶点挪到显卡上**：对偶四元数蒙皮写进着色器，主线程每帧只传 97 根骨骼的矩阵，顶点多少都不到 1 ms。导出、落地、点选还用现在 CPU 那一套。阴影那一遍也要同样改，风险在着色器补丁和三种材质。

预计：每次拖动 11–14 ms → 3–5 ms（3a、3b）→ 不到 1 ms（3c）。
验收：拖到同一个姿势，屏幕上的顶点和现在一样（3a、3b 逐值一样，3c 截图对比）；导出摆好姿势的模型不变。

### 第 4 期：主线程上的零碎

改 `src/main.ts`、`src/character/tweak.ts`。

- 拖着的时候不每动一下就存档（松手再存）、不重画整个面板（只更新微调那几格数字）、记撤销不再把整份设定转成文字比较；开发时那个「描述再解析一遍」的检查拖动中跳过。
- 成品角色拖动时，选中部件的顶点权重（`weightsOf`）按部件留着，不每帧重算。

预计：造型时每帧主线程少 2–5 ms，成品角色拖动 58 帧 → 80 帧以上。这台电脑上不明显，手机、用电池时有用。
