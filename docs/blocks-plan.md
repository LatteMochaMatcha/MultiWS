## 一句话说清要做什么

现在的工坊是「填数量 → 程序排好」，用户只能在排好的结果上挪一挪。这份方案加的是另一条路：**把身体当成几块能自己拼的体块**——能复制一块、能挪到任何地方、能接到别的体块上跟着它走。

四个动作凑成一套：

| 动作 | 现在有没有 | 这份方案 |
|---|---|---|
| 挪、转、缩放一块 | 有（手动微调） | 不变 |
| 删掉一块 | 有（2.8.1 加的） | 不变 |
| **复制一块**（连同长在它上面的） | 没有 | 第 1、4 期 |
| **接到另一块上**（缝合，之后跟着它动） | 没有，谁跟着谁是写死的 | 第 3 期 |

再加两样配套：躯干分成「胸腔」和「胯和小腹」两块（第 2 期），连接点吸附（第 5 期）。

## 现在是什么样（都在代码里核对过）

**部件怎么切的**

- 头、脖子、每条手臂、每条腿、每只胸、尾巴、翅膀、角、耳朵、眼睛，已经各是一个独立部件，能单独挪、转、缩放、删。
- **躯干是一整块**。白模人台是一条从胯底到脖子根的放样（`layout.ts` 1081–1148），腰、胯、屁股都在里面；二次元素体是一块从裆到脖子根的采样格子（`animeLayout.ts` 484–514），也含胯和屁股。
- 只有两种情况躯干是分开的：「多个上半身」时在腰上切成「躯干（腰以下）」+「上半身 左/中/右」（`torsos.ts` 的 `splitTorsos`，只有一个上半身时直接原样返回，第 207 行）；「前后排」里每个人复制成上下两份、各用一个大椭球削掉一半（`ring.ts` 1330 起的 `halved`）。
- 成品角色不切网格，部件就是一串骨骼；单个上半身时「躯干」是脊柱往上的全部，不含胯（`character/tweak.ts` 89）。

**谁跟着谁动**

- 躯干带着脖子、头、手臂、胸、翅膀；头带着眼睛、角、耳朵；**腿、尾巴、兽身各自独立，挪躯干时腿不跟着**（`geometry/tweak.ts` 开头的约定）。
- 父子关系是摆位时写死的（`Part.parent`），没有任何改它的办法，`PartOverride` 里也没有这一项。
- 多选能一起挪，但选中状态不保存；一起转的时候**每个部件绕自己的关节转**，不是整体绕一个点转（`main.ts` 2506 的 `applyTweak`）。

**胸**

- 白模的胸是挂在躯干上的普通椭球，能随便挪。
- 素体的胸是「贴在躯干表面上的一片」（`ChestShape`，`surface: true`），手动微调只能沿着表面滑。围成一圈、前后排里用的是另一种「只取胸、不带底下那片皮」的取法（`ChestShape.piece`），那种能随便挪。

**楚云萱（前后排）是怎么拼出来的**

把整个人复制几份、转过去，再垫一根芯子、垫胸底、填缝（`ring.ts` 的 `Core`、`ChestPad`、`RowFill`）。所以关掉融合看到的是一堆完整的上半身叠着——截图里说的属实。11-14 到 11-15 修的沟、洞、台子、鼓棱，大半是整个人互相叠出来的。

**管线上别的环节对部件有什么要求**

| 环节 | 对新体块的要求 | 能不能直接走通 |
|---|---|---|
| 融合 | 部件的类型在 `sdf/field.ts` 的 `GROUPS` 里就行，实例名不用登记 | 能 |
| 分部件模式 | 每个部件单独出网格，切口是封口的 | 能 |
| 骨架 | 骨骼名全身唯一，只能有一根根骨骼（`rig/skeleton.ts` 61–86） | 复制时改好名就能 |
| 蒙皮 | 完全埋住的体块不分权重，不会乱；但「这个顶点是哪个人的」是按名字 `UpperBody`、`Torso_X` 认的（`rig/skin.ts` 378–390） | 四肢能，多出来的胸腔要补 |
| 摆姿势 | 圆点照骨骼名生成；松手后重新融合里有按名字 `Torso`、`UpperBody*`、`Torso_C` 的特判（`sdf/posedField.ts`） | 四肢能，胸腔、胯要补 |
| 现成姿势 | 多出来的手臂照序号跟着第一对；不认识的骨骼保持不动 | 四肢能 |
| 导出 VRM | 多出来的骨骼不进人形对照表，作为普通骨骼 | 能 |
| 穿模检查 | 只在开发模式跑、只进控制台 | 不影响用户 |

复制部件现在**没有通用的函数**：多个上半身、围成一圈、连体三处各写各的改名（`torsos.ts` 392、`ring.ts` 818、`conjoined.ts` 146），每处都要同时改部件名、父部件、骨骼名、骨骼的父骨骼、手上那块现成网格的骨骼名。

## 设计

### 体块是什么

就是现在的「部件」，不另造一套东西。新增的只是三样数据，都存在角色设定里、跟着存档和撤销走：

```ts
// model/spec.ts，加在 BodySpec 上（名字开工时再定）
blocks?: {
  /** 用户加出来的体块：照哪个部件复制的、连不连它上面长的 */
  added: { id: string; from: string; subtree: boolean }[];
  /** 缝合：部件名 → 接到哪个部件上（可带连接点的名字） */
  attach: Record<string, { to: string; socket?: string }>;
  /** 躯干有没有分成胸腔和胯腹两块 */
  splitTorso?: boolean;
};
```

没有这一项的旧存档、默认形态，出来的模型和现在**一模一样**（每一期都拿这个当验收条件）。

### 躯干分成两块，不是三块

提议原话是「独立的胸腔体块，独立的头部体块，独立的胯部和小腹体块」——这正是画人体时的三大体块：头、胸腔、骨盆，腰是连接处。所以躯干在**腰最细处**分成两块：

- **胸腔**：腰以上到脖子根，带着脖子、头、手臂、胸、翅膀；
- **胯和小腹**：腰以下，带着腿、尾巴（现在腿不跟躯干，这里改成跟着胯）。

这样分有现成的路：`torsos.ts` 的 `splitTorsos` 已经会在腰上把白模的放样、素体的格子切成两截，两截各多留 1 厘米互相埋着、同一类直接并在一起看不出缝；上半身被手动挪过、转过以后，`refork` 会把腰重新接顺。现在它在「只有一个上半身」时直接跳过，第 2 期要做的是让一个上半身也能走这条路。

分三块（胸腔、腰腹、胯）的话没有现成的路：摆姿势后三块各弯各的、接缝会裂（`posedField.ts` 1198 起：每个躯干类部件只顺自己的骨骼弯，只有多个上半身的素体走「一起弯」那条路），素体格子的拉长、加宽、并身那些变形三块都得给一模一样的参数。不建议。

**没动过就不切**：只有用户单独动了胸腔或胯腹、或者加了体块，才真的切开（`splitTorso`）；否则还是一整块。这样默认形态和所有旧存档零风险。

切开的两头都要是完整的：单独挪开的胸腔底下、胯腹顶上各垫一个圆顶（围成一圈里「多出来的胯」已经是这么做的），不留平的切面，也不用挖刀削。

### 复制

点中一个部件 →「复制一份」→ 多出一个一样的，往旁边挪开一点，接在同一个父部件上，自己有自己的微调。

- 连同长在它上面的一起复制：复制头带着脖子、眼睛、角、耳朵、头发；复制胸腔带着脖子、头、手臂、胸；复制胯腹带着腿。
- 新建一个通用的复制模块（`geometry/clone.ts`）：一次把部件名、父部件、骨骼名、骨骼的父骨骼、手脚那块现成网格的骨骼名都改好。先只给新功能用，不去动 `torsos.ts`、`ring.ts`、`conjoined.ts` 里已经稳定的三份。
- **名字用单独的号段**：复制出来的从 51 号起（`Arm_51_L`、`Head_51`、`Chest_51_L`）（做的时候改成了 100 × 第几块 + 原来的号，见「第 1 期做完的样子」）。这样以后把「手臂几对」从 3 改成 4，程序排出来的 `Arm_04` 不会和用户加的撞名，用户加的那些的微调也不会对到别的部件上。我看过的几处按名字认部件的地方（`ring.ts`、`conjoined.ts` 的编号正则 `(\d+)`、`partLabel.ts`、`Neck_→Head_`、`_L/_R` 镜像）都认多位数字；第 1 期开工时把全项目按名字认的地方再逐个过一遍。骨骼名照现有的编号规矩接着编，这样「多出来的手臂跟着第一对摆」那套不用改。
- 复制出来的素体的胸不贴表面（`piece` + `surface: false`），**想放哪放哪**：肚子上、背上、大腿上都行。原来那些贴着表面的胸不变。

### 缝合（接到另一块上）

点中一个部件 →「接到…」→ 再点目标部件。之后：

- 它（连同它上面长的）变成目标的子部件：**挪、转、缩放目标，它跟着走**；挪它自己，只是改它在目标上的位置。这就是截图里说的「缝合两个体块，将他们视为一个整体，可以移动」。
- 接上去的那一刻它在原地不动（位置换算到新的父部件里），不会跳。
- 骨骼跟着改接：它的根骨骼改挂到目标最近的那根骨骼上。这样摆姿势时它也跟着目标动，蒙皮时也算在一起——只在微调里一起挪做不到这一点。
- 「解开」就回到原来的父部件。不能接成环（A 接 B、B 又接 A），界面上直接不让选。

**不另做「编组」**。上一轮我提过「缝合成组」（把几个部件记成一组），仔细想过以后不建议：有了「接到」，一组就是一棵接起来的树，两套东西并存用户分不清哪个管哪个。多选保留，另外补一样：多选一起转的时候可以选「整体绕一个点转」（现在是各转各的）。

### 连接点

每种体块上有几个固定的接口：

| 体块 | 接口 |
|---|---|
| 胸腔 | 脖子根（每个脖子一个）、左右肩、腰（底下） |
| 胯和小腹 | 腰（顶上）、左右髋、尾根 |
| 头 | 脖子（底下） |
| 脖子 | 上下两头 |
| 手臂、腿、尾巴 | 根部 |

- 手动微调时接口显示成小标记；把一块拖到能对上的接口附近，它吸过去（位置和朝向都对上），同时自动接上。
- 接在接口上的，记的是接口的名字（`attach[...].socket`）。以后改肩宽、身高这类体型滑块，接口挪了，接在上面的体块跟着挪——只记坐标的话会留在原地。
- 接口的位置从已有的数据来：骨骼的头尾（肩、髋、脖子根、腰都有对应的骨骼关节），不用另外量。

吸附只是省得手对；不用接口、随便放在哪再「接到」也一样成立。

### 和现有功能的关系

- **数量设定、排法（多对手臂、多头、多腿、多个上半身）照旧**。体块是叠在排好的结果上面的：先照数量排，再套「加的、接的」，再套微调。插入点在 `layout.ts` 的 `buildFigure`：`layoutFigure` 之后、`applyOverrides` 之前。
- **围成一圈、前后排、连体不重做**，照旧生成；生成出来的部件一样能复制、接、挪。要注意的一点：这几种形态里改了人数，部件会重新编号，原来记在某个名字上的「接到」可能对到别的部件上——和现在微调的老毛病一样。对不上的那几条丢掉并提示，不硬套。
- **换预设**：和微调一样，加的体块、缝合全部清掉（它们是针对上一个角色做的）。
- **多角色场景**：每个角色各存各的，不用改。
- **成人部件**：`model/adult.ts` 会筛微调，加的体块里有成人部件时照同样的规矩藏。

## 可以借鉴的（2026-11-16 上网查的）

没有找到哪个 Blender 插件是「把角色体块拼起来、自动融合、自动带骨骼」一整套的。能借鉴的是几样各管一段的东西。下面每条写了它是什么、借什么、落在哪一期。

| 来源 | 它是什么 | 借什么 | 落在 |
|---|---|---|---|
| 《孢子》生物编辑器（Hecker 等，SIGGRAPH 2008 论文，读了第 2–5 页） | 玩家在一根脊柱上随便接肢体，动画要套到没见过的身体上 | 见下面三条 | 第 3、4 期 |
| Joint Snapping System（Blender 付费插件，看的是商品页） | 给模块化零件定义带朝向、带标签的接口，按接口对接 | 见下面 | 第 5 期 |
| Fusion for Blender（付费插件，看的是文档页） | 把两个相交的物体融成一个，像融球那样过渡，随时能拆开 | 融合是「一对一对」的，每一处有自己的参数，每一处能单独拆 | 候选 |
| Arcane SDF、Chisel 等 SDF 建模插件 | 在 Blender 里用距离场拼形状 | 每个形状自己的圆滑半径；形状能改挂、复制、成组（Arcane SDF 的商品页这么写） | 候选 |
| Auto-Rig Pro、Rigify | 骨骼是一段一段「肢体模块」拼的，能加、能复制肢体 | 复制肢体要走专门的操作统一改名，直接复制骨头不行（论坛里用户的说法）——和 `clone.ts` 是一个思路 | 第 1 期 |
| Smart Mesh Blend（Blender 插件，看的是报道） | 不改网格，只把挨着的物体的法线按距离混在一起，接缝看不出来 | 成品角色的体块是插在一起不融合的，接缝可以这样藏 | 第 6 期候选 |
| Proko 的人体课 | 画人体的三大体块：头、胸腔、骨盆 | 躯干分两块（胸腔 + 骨盆）就是这个分法 | 第 2 期 |

没查到的：Design Doll、Easy Poser 这类摆姿势软件怎么加多条手臂（搜不到）；中文的多肢体拼装插件或教程（搜不到）；Hecker 的个人网站当时打不开，「孢子的皮肤是一整块融球、没来得及做融球分组」这句只在搜索摘要里看到，没读到原文。

### 从《孢子》借的三条

1. **只能接成树，不能接成环。** 论文脚注说早期原型支持环这类更一般的结构，测试下来界面太复杂、反而妨碍玩家。方案里「接到」本来就不让接成环，这是旁证，不用再犹豫。
2. **认部件靠「是什么 + 长在哪」，不靠名字。** 孢子给每一块打能力标签（抓握的、嘴、脊柱、根），选部件用「种类 + 方位」的说法：前/中/后、左/中/右、上/中/下，「最前面的那个」，还能从手往上走到最近的那节脊柱找到肩。工坊现在很多地方是按名字和编号认的（`UpperBody`、`Torso_C`、`.00N`），用户自己接的体块名字不带这些信息。**第 3、4 期改成按部件的种类和它相对自己那块胸腔、胯的方位来认**，这也是「一条腿接到胸腔上以后现成姿势怎么套」的答案：它还是腿（种类没变），方位照它现在长的地方算。
3. **姿势照「相对静止姿势的变化」记，再按肢体长短缩放。** 孢子的动画不记绝对位置，记的是「比静止时往前伸了多少」，伸多少按肢体的长度比例放大缩小；要碰地的用「离地面的比例」记；「手放到嘴边」这类用「朝另一个部件走了几成」记。工坊的现成姿势现在主要照骨骼转角套，标准身材没问题；用户把肢体接到奇怪的地方以后，转角照搬会穿进身体。第 4 期遇到摆不顺的，照这三种记法补，不另想办法。

另外两点：孢子把「玩家摆成什么样」直接当静止姿势，不要求标准站姿——工坊也是这样；多个头朝不同方向时，看向目标只让朝着那边的头转——以后做「看向」时用得上。

### 从 Joint Snapping System 借的（第 5 期的细节）

- **接口带标签**：接口和零件各有标签，标签对得上的才能接（肩的接口收手臂、翅膀；髋的接口收腿；脖子根收脖子）。对不上的也让接，只是不吸附。
- **两下点接**：先点目标的接口，再点自己的接口，两个接口对齐。比拖过去吸附更准，手机上也好用。两种都做。
- **只对位置**：对接时可以只对上位置、不改朝向。
- **接着的时候绕接口转**：对接以后还能绕接口的轴一格一格转，不脱开。
- **一次填满**：往所有同类的接口上各放一份（比如每个肩上都接一条手臂）。放到第 7 期再看要不要。

### 两个候选（默认不做，要的话你点名）

- **每一处接缝自己的圆角**：现在融合的圆滑程度是全身一个数、再按部件种类打折。可以让接上去的每一块自己带一个「接缝多圆滑」，比如背上的胸要软、角要利落。要改距离场怎么并（`sdf/field.ts`），那是胸躯干会话的文件。
- **只有接在一起的才融合**：现在碰到一起的都融成一片，手臂搭在胸上会长在一起，这是好多「蹼」的来源。孢子当年也是整块融、没来得及分组。如果改成「只和自己接着的那一块圆滑融合，碰到别的只是贴着」，蹼会少一大类。代价不小：融合的顺序、蒙皮、松手后重新融合都要跟着改，而且现在很多形态（围成一圈、多个上半身）正是靠碰到就融才成一整块的。只适合在体块功能稳定以后单独立项。

### 第 2 期做完的样子（2026-11-16）

设定 `BodySpec.blocks.splitTorso`；手动微调里选中躯干时多一个按钮「分成胸腔和胯」（分开以后是「合回一整块躯干」）。分开以后是两个部件：**胸腔**（`UpperBody`，带着脖子、头、手臂、胸、翅膀）和**胯和小腹**（还叫 `Torso`，带着 Hips 骨骼）。测试 `tests/splitTorso.test.ts`（16 项），出图 `node tools/run.mjs tools/try-blocks.ts --case split`。

做法：

- **切法直接用多个上半身那一套**（`torsos.ts` 的 `splitTorsos` 多了一个参数 `one`）：一个上半身也在胯上切开，这一个不歪不挪、胯不加宽，部件名、骨骼名都不变。分开的那一段从髋关节那么高一直到胸下面（和多个上半身一样），所以小腹、腰是连接的那一段。并成宽躯干的（`GridShape.twin`）切不了，照没分开的摆。
- **两块是各自独立的**（和原先打算的「胯带着整个上身」不一样）：胸腔不挂在胯上，两个都没有父部件。挪、转、缩放胸腔，胯和腿不动；挪、转、缩放胯，胸腔不动。中间的腰由 `refork` 照两块现在的摆放接顺（`placement` 里把不挂在胯上的胸腔换算成相对胯的摆放）。这样才是「独立的胸腔体块、独立的胯和小腹体块」；胯要是带着整个上身，挪胯就等于挪整个人，没有用。
- **胯带着腿走**（`tweak.ts` 的 `movePelvis`）：胯的微调另外套，没有父部件的部件（腿、尾巴、垫在腿根上的那些）都跟着它挪、转、等比放大，各自不变形；之后整个人升降到脚还踩在原来的地面上。所以把胯往上挪 5 厘米，结果是腰短了 5 厘米。胯转、缩放时绕髋关节那么高的正中。
- **摆姿势**：松手后照姿势重新融合时，两块躯干一起顺着所有躯干骨骼弯（`posedField.ts` 的 `shared`，素体本来就是这样处理多个上半身的，白模人台这次也加上了）。不这样的话胯只跟着 Hips、胸腔从 Spine 弯起，切口那里错出一圈台阶（白模出图时看到的）。
- **分开、合回去时微调怎么带**（`model/blocks.ts` 的 `setSplitTorso`）：整块躯干的微调分开时挪到胸腔上，合回去时挪回来；胯自己的微调合回去时丢掉。
- 界面上两块叫「胸腔」「胯和小腹」（`partLabel.ts` 的 `labelSplitTorso`，每次重建模型以后告诉一声）；多个上半身时原来的「上半身 左/中/右」「躯干」不变。
- 连体、围成一圈、前后排、几个上半身、成品角色不分（设定里记着也不起作用）。

出图看过的（两种白模）：没切开、切开没动（表面差不到 0.3 毫米，测试里打射线量的）、胸腔前倾 20°、歪 15°、拔高 10 厘米、扭 30°、左挪 6 厘米、胯歪 12°、胯放大 1.25、胯后挪 6 厘米——都是一整块封闭网格，腰是顺的；每种套「弯腰拿东西」「蹲着」。页面里点过：分开、自动选中胸腔、改角度、存档。全套测试 1998 项通过。

和原先打算不一样的、没做的：

- 原先写的是「点躯干时面板上选 整个躯干 / 胸腔 / 胯和小腹，第一次单独动其中一块时才切开」，做成了一个明确的开关：切开没动时样子不变，开关比「悄悄切开」好懂。
- 「两块离得太远接不上时各自封圆顶」没做：现在腰是一直拉着的，拉得很远会拉成一根细长的腰。
- 胯等比以外的缩放（只加宽）时腿只跟着挪位置，不跟着变粗。
- 胸腔前倾得多时，胸下面有一道折痕（分开的那一段到胸下面为止）。
- 手机界面没看；导出没进 Blender 看。

### 第 3 期做完的样子（2026-11-16）

设定 `BodySpec.blocks.attach`：部件名 → `{ to, pos, quat, scale }`。手动微调面板多了「接到…」「解开」两个按钮和多选时的「像一整块那样转动、缩放」。代码：`src/geometry/attach.ts`（摆好的 Figure 上改父部件、骨骼改接）、`src/model/attach.ts`（设定上接、解开，换算位置）、`src/geometry/hostBone.ts`（找最近的骨骼，和复制出来的胸共用）。测试 `tests/attach.test.ts`（20 项）、`tests/ai.test.ts` 里三项；出图 `node tools/run.mjs tools/try-blocks.ts --case attach`。

做法：

- **接上去记的是「它在新父部件自己坐标里的摆放」**（和原先打算的「只记接到谁」不一样）：只记接到谁的话，每次重建都得拿它自己原来摆位的地方去换算，新父部件因为体型、数量变了挪了位置，它不会跟着。记了摆放，它就一直在新父部件身上的老地方。
- **接上去、解开都不跳**：接的时候照它现在在世界里的摆放换算（新父部件被拉伸过——手动微调、手臂长短滑块——也算进去了），它原来的位置、角度、等比大小的微调并进这个摆放里，只留下各方向不一样的那部分拉伸；解开的时候反过来，把现在的摆放换算成一条手动微调。测试里量的是差不到 0.1 毫米（解开 0.2 毫米）。
- **骨骼跟着改接**：接出去的部件根上的骨骼，接到新父部件（它没有骨骼就再往上）离它最近的那根上；套完微调以后照最后的位置再定一遍（`rehost`）。头带着自己的脖子一起接，头的骨骼还接着那根脖子。这样摆姿势、蒙皮时它真的是跟着新父部件的。
- **照原位做的形状换成能摆到别处的**（和复制用同一个 `loose`）：素体的手臂、脖子、贴着表面的胸；胸带上自己的骨骼。腿接出去以后不再当成胯的一部分，「垫在腿根上的胯跟着腿收窄放宽」也不算它。
- **不会绕成圈**：接到自己、或者长在自己上面的部件上，界面上提示接不上；存档里手改出来的圈，后接的那一条不起作用。骨骼会绕成圈的也不改接。
- 两头的部件有一个现在不在（改了数量、合回了躯干）的那一条不起作用，设定里留着，部件回来了又生效。删掉手工加的那一块时，它的缝合一起去掉。
- 勾着「同时调整对侧」接的时候，对侧那个接到对面对应的部件上（目标不分左右就是同一个）；解开也是两边一起。
- **多选「像一整块那样转动、缩放」**：别的部件除了照同样的量转、等比缩放，还绕操纵杆所在那个部件的支点挪过去（`model/overrides.ts` 的 `rigidDelta`）。不勾还是各自绕自己的关节。各方向不一样的缩放不挪。
- **AI 助手**多了三个工具：`copy_part`、`attach_part`、`detach_part`；改动清单里会写「复制出…」「…接到…上」「解开…」「躯干分成胸腔和胯两块」。

出图、页面里看过的：复制一个小头接到左上臂、复制一只胸接到左大腿、右手臂接到头上，两种白模，静止是一整块封闭网格，套「张开双臂」「叉腰」「蹲着」时都跟着接的那个部件走；页面里把复制出来的一对手臂接到头上，歪头，手臂跟着。

没做的、还在的：

- 「能接的亮、不能接的暗」没做，接不上时面板上说一句。
- 现成姿势对接到别处的肢体还是照它原来是什么来套（腿还是照腿摆），没有照它现在长的方位调；摆得顺不顺只看了上面那三个姿势。
- 多选「像一整块」只有测试（`tests/rigidTweak.test.ts`），页面里只确认了开关出现，没有实际拖过操纵杆。
- 手机界面没看；导出没进 Blender 看。

### 第 4 期：复制胸腔、复制胯

做什么：

- 第 1 期的复制放开到胸腔（带脖子、头、手臂、胸）和胯腹（带腿）；
- 多出来的脊柱骨骼改名（照围成一圈的规矩 `Spine.00n`）并挂到接的那块上；
- 蒙皮里「这个顶点是哪个人的」从按名字认改成按「它属于哪个胸腔」认（`rig/skin.ts`），多个上半身、围成一圈原来的结果不变；别处按名字、编号认躯干和肢体的地方也照「种类 + 相对自己那块胸腔或胯的方位」改；
- 松手后重新融合里按名字的特判补上加出来的胸腔、胯；
- 现成姿势：加出来的胸腔上的手臂照它自己胸腔的朝向套（连体、围成一圈都有先例：`pose/conjoined.ts`、`pose/ring.ts`）。

怎么验：一个胯上放三个胸腔（自己摆成扇形）；两个胯上下叠；照楚云萱的参考图手工拼一个前后排，和程序排的并排比。全部套姿势、导出。

风险：高，但比第 2 期好控制——多出来的胸腔在多个上半身、围成一圈里已经走通过，这次是把「靠名字认」换成「靠接在哪认」。部件多了以后的速度：蒙皮的耗时大约是顶点数 × 部件数，一个加了六个胸腔的角色和现在的楚云萱差不多重，开工前先量一遍楚云萱当基线。

### 第 5 期：连接点吸附

做什么：接口的定义（上面那张表，带标签）、微调时显示、拖近了吸附并自动接上、两下点接、只对位置、接着的时候绕接口转（后四样见「从 Joint Snapping System 借的」）、`socket` 存进 `attach`、体型滑块动了以后跟着走。

怎么验：把加的手臂拖到另一个胸腔的肩上松手；改肩宽看它跟不跟；手机上手指拖也吸得上。

风险：低到中，主要是手感（多近算近、吸过去以后还能不能再微调）。

### 第 6 期：成品角色

成品角色是另一条管线（直接复制 VRM 的网格和骨骼来拼，不融合）。能做的：

- 胸腔、胯分开挪：照骨骼分（胯 = Hips，胸腔 = 脊柱往上）。调查的判断是三种样式里这个最容易；
- 复制头、手臂、腿：多头、多手臂本来就是复制拼的，有路；
- 复制胸腔：多个上半身时已经会照「跟着脊柱的权重」复制，有路；
- 复制出来的东西和身体之间**不融合**，是互相插着的，衣服花纹不连续——这是成品角色一直以来的样子。

做不做、做到哪见「要你定的」第 4 条。

### 第 7 期：收尾

- 新手引导里加一步；README 和三份使用说明各加一小段；CHANGELOG；
- 文字描述（`parser/describe.ts`）提一句「另有 N 块手工加的体块」；
- 手机界面：复制、接到、解开三个按钮进抽屉；「接到…」的挑选状态在手机上怎么取消；
- 预设：加一两个用体块拼的例子；
- 全套出图总览重测（`tools/overview.ts`）。

## 不做的

- **hardness 版**：用户说先不管。
- **把躯干切成三块以上**（胸腔、腰腹、胯；或者再把肩带、臀单独切）：理由见上。
- **重写围成一圈、前后排**：先不动。体块稳定以后再评估要不要让前后排改用「胸腔 + 胯」来拼、去掉现在削掉一半的那个大椭球（见「要你定的」第 6 条）。
- **编组**：用「接到」代替。
- **空白开局**（从零开始一块一块拼一个人）：总是从一个排好的角色开始加减。

## 要你定的

每条前面是我的建议。

1. **躯干分两块**（胸腔 + 胯和小腹，腰是接缝）。另一种是三块，代价和风险高很多。
2. **没动过就不切开**。默认形态和旧存档完全不变；代价是代码里多一个「切没切」的分支。
3. **在哪个会话做、谁改胸躯干那几个文件**。第 1 期要碰 `animeLayout.ts` 胸那几行，第 2、4 期要大改 `torsos.ts`、`animeLayout.ts`、`posedField.ts`、`skin.ts`——按 11-01 定的规矩这些只归「胸部、上半身和多胯修复方向」那个会话改。建议：整个方案在这个会话里做，另开 worktree `F:\Downloads\多tool-blocks`、分支 `feature/blocks`，开工前你告诉胸会话这段时间别同时改这几个文件；每期做完合回主线。
4. **成品角色放最后，先只做「胸腔、胯分开挪」**，复制体块看前五期的效果再定。
5. **入口放在手动微调面板里**（复制、接到、解开三个按钮），不另开一栏「组装」。它们都是「点中一个部件以后做什么」。
6. **前后排（楚云萱）现在不动**，等第 4 期做完，拿「手工用体块拼的」和「程序排的」并排比过，再定要不要改程序排的那一套。
7. **不设体块个数上限**，部件多到明显变慢时在界面上提示一句（多角色场景当时也是不设上限）。

## 做的时候要守的规矩

- 身体的每一块都要完整（11-15 定的）：分开的地方封圆顶、靠摆位贴着，不用切口把相邻的体块削平。
- 照参考图调形态时先叠图、并排量，再动参数。
- 不下载新素材；这份方案用不到新素材。
- 进 `docs/` 的图一张 300 KB 以内、要被文档引用；临时出图放 `.harness-tmp/`。
- 界面文字包 `t()`，补英文、日文译文。
- 用户在玩游戏时测试少开线程；验打包的 exe 用别的端口和临时状态目录。
