# 一个场景里放好几个角色：方案

2026-11-07 用户要「多素体功能 多角色」，问清楚以后是：**一个场景里放好几个独立的角色**，每个各有各的设定、各摆各的姿势，一起显示、一起导出。

和已经有的「多个上半身」「男女连体」不是一回事：那些是一个身子上长好几份；这里是好几个人，各自一个身子，站在同一块地上。

## 现在是什么样

- 一个角色的全部东西都在一份设定 `BodySpec` 里：数量、排布、体型、样式、成品角色、头发、微调（`characterOverrides`）、表情，连摆的姿势（`posing`）也在里面。再加一段描述文字。
- `main.ts` 里这些都是**只有一份**的全局变量：`spec`、`text`、撤销历史 `history`、几种显示用的模型（`model`、`fused`、`characterModel`、`flatParts`）、摆姿势的 `kit` / `posed`，四个模型的根挂在场景上（`viewport.scene.add(...)`，1163 行）。
- 存档：浏览器里一个键 `oc-basemesh-v2`；「保存配置」「保存姿势」各存一个文件。
- 导出：GLB / 带骨骼 GLB / OBJ / STL / VRM 都只写一个角色；`writeGlb` 只认一副骨架。

## 总的做法：每人一份设定，同一时间改一个

不把 4300 行的 `main.ts` 拆成「每个角色一套」，而是：

- 场景是一张**角色清单**，每个角色存一份设定 + 描述文字 + 摆在哪（地上的位置、朝哪）+ 名字。
- 同一时间只有一个是**当前角色**：现在整套界面、撤销、摆姿势、导出代码照旧只对着它，完全不用改。
- 别的角色显示成**定住的网格**：切走时把当前画面上那份网格（融合的、分部件的、成品角色的、摆好姿势的，看到的是哪个就是哪个）复制一份留在场景里，不重算。
- **切换角色** = 把当前的设定写回清单里自己那一格，把另一个读进来，和撤销恢复走同一条路（`restore`），重建一次。点场景里别的角色，或者点角色条上的头像，都能切。
- **当前角色永远站在原点**，别人照「相对它在哪」摆。这样点选部件、拖操纵杆、摆姿势的拖手柄、穿模检查这些用世界坐标的代码都不用动；切换时相机跟着平移，画面不跳。

另一种办法是真的每个角色各一套模型、全部同时能改。要把 `main.ts` 里几百处全局变量都改成「哪个角色的」，工作量大几倍，还会和别的会话正在改的地方撞车，不推荐。

## 分期

### 第 0 期：准备

- 工作区里有别的会话 11-07 没提交的「手指、脚趾数量」改动（`main.ts`、`spec.ts`、`index.html`、i18n 等），这个功能也要改这几个文件：**等那边提交以后再开始**，在单独的分支上做。

### 第 1 期：数据和存档（不动界面）

- 新文件 `src/model/scene.ts`：场景 = `{ figures: [{ id, name, spec, text, place: { x, z, yaw } }], current }`；增删、复制、改名、切换、整理（读旧存档、坏数据）都是纯函数，带测试。
- 浏览器存档加一个新键（`oc-basemesh-scene`）存整个场景；旧键 `oc-basemesh-v2` 照旧写当前角色，这样退回旧版本（自动更新能回退）也不丢东西。
- 只有一个角色时，所有行为和现在一模一样。

### 第 2 期：角色条和切换

- 3D 视图上方（电脑版）一排角色头像：每个是名字 + 小截图，当前的高亮。按钮：**新建**（默认的白模）、**复制当前的**、删除（要确认，删了能「恢复刚删的」）、改名。
- 点头像或点场景里别的角色就切过去。
- 撤销：每个角色**各自一条**撤销历史，切走时连同它一起存在清单里；切回来接着撤。
- 定住的网格：切走时复制；打开页面时（从存档恢复，还没有网格）在后台挨个建一遍，先用粗网格，建好之前显示一个灰色的人影占位。
- 状态栏的三角面数加上「场景合计」。

### 第 3 期：摆位置

- 选中某个角色时它脚下有一个底座圈：拖圈挪位置、拖圈上的小把手转朝向；面板上也有 X、Z、朝向三个数字格。
- 新建、复制的角色自动找旁边的空地站（照包围盒，间隔 30 厘米）。
- 视图按钮加「看全部」「看当前」；地面、阴影、取景照全场景的包围盒。

### 第 4 期：保存场景文件、导出

- 「保存配置」照旧存当前角色；新加「保存场景」存整张清单（一个 JSON 文件），「打开」认得两种文件。
- 导出时问「只导当前角色」还是「整个场景」：
  - **GLB（不带骨骼）**：每个角色一组物体，摆在各自的位置。
  - **带骨骼 GLB**：每个角色一副自己的骨架（`io/glb.ts` 要改成能写好几副骨架、好几个蒙皮），进 Blender 是几个骨架物体。
  - **OBJ、STL**：所有人的面写在一个文件里，物体名带角色名。
  - **VRM**：一个 VRM 文件只能是一个人，只导当前角色（不问「当前还是整个场景」）。
  - **截图**：本来就拍整个画面，不用改。
- 导出整个场景时，别的角色要照导出精度重算（定住的网格是屏幕上的粗细）：在后台另开一份模型挨个算，界面不切过去，状态栏显示「第 2 个 / 共 4 个」。
- 用到要署名素材的：几个角色的署名合在一起写进文件。

### 第 5 期：收尾

- 手机版：角色条放在 3D 视图底下一行，可以左右滑。
- 新手引导加一步、英文日文译文（新文字都包 `t()`）。
- 画红圈问题单记下场景里有几个人、当前是哪个；`tools/agent.mjs model` 也能读整个场景。
- 性能：同一个成品角色用好几次时贴图共用；数量不设上限，人多时提示一句。
- 全套测试，在单独的 5181 端口上看，重打 exe / apk。

### 以后再说（这次不做）

- 角色之间的互动：两个人手拉手（把手拖到另一个人身上对齐）、跨角色的穿模检查、双人姿势预设。
- 一个场景里同时编辑好几个人。

## 已定的事（2026-11-07 用户定的）

1. **编辑方式**：同一时间改一个，别的定住，点别人切过去。
2. **角色数量不设上限**（用户原话「卡了自己负责」）。第 5 期的「设上限」不做；人多时状态栏提示一句可能会卡，不拦。
3. **VRM 只导当前角色**，和现在一样，切到谁导谁。
4. **撤销每个角色各自一条**，切回来接着撤。

## 风险

- 定住的网格和真算出来的会有一点不一样（屏幕上是拖动时的粗网格时）：切走前等精细网格出来再复制。
- 打开一个四五个人的存档，后台挨个建要十几秒到几十秒：先显示占位，当前角色优先。
- `main.ts` 里切换角色要把所有「只为这一个角色」的缓存清干净（成品角色的 `characterBase`、摆姿势的 `kit`、选中的部件、手柄……），漏一个就会串到下一个人身上。第 2 期专门测「切走再切回来，样子、撤销、选中都对」。

## 做成了（2026-11-07，分支 feature/scene，worktree F:\Downloads\多tool-scene）

六期一次做完。和上面打算不一样的几处：

- **别的角色怎么算**：不是「切走时复制屏幕上那张就完事」，而是写了 `src/scene/bake.ts`：只凭一份设定算出它摆好姿势的样子，不碰界面上的任何全局状态（当前角色正在改的时候也能算别人）。融合的白模用自己的网格线程（`MeshClient`，自己排队），屏幕上用预览精度、导出用精细的；分部件的在主线程算；成品角色照拼好、套微调、摆姿势（`poseBuild`）。摆过姿势的不管现在在哪一页，都照摆好的样子。眼睛标记跟着头的骨骼走，只上屏幕不导出（和当前角色一样）。
  切走那一刻屏幕上那张网格复制成灰色的人影先顶着（`SceneFigures.setGhost`），后台算好再换；设定没变过的直接用上次算好的。打开页面时别人先是一根灰柱子，后台挨个算。
- **切过来时**：当前角色的四个模型放在一组（`live`）里，新角色自己的网格算出来之前整组藏着，原点上接着显示它定住的那份（`holdLive`，融合的等 `FusedModel.caughtUp`，最多 15 秒），免得原点上闪一下上一个角色。
- **摆位置**：底座圈谁都能拖，不用先切过去。拖别人的那一步记进它自己的撤销历史；拖当前角色的记进当前的（撤销快照里多了 `place`）。拖当前角色时别人和镜头反着挪，屏幕上看是它自己走过去。滑块：左右、前后（±20 米，一格一厘米）、朝向，「朝向回正」。
- **角色条**放在 3D 视图左上角（电脑），手机竖屏在读数下面一行、能左右滑；只有一个角色时不出现，最后一个是「+」（打开「场景」那一栏）。
- **删除**用工坊自己的确认框（`askDialog`，点按钮当场作数，不等 close 事件：页面藏着时它不来），只记最后删的一个，能「恢复刚删的」。
- **场景文件**：「打开场景…」认两种：场景文件换掉现在全部角色（好几个角色时先问），一个角色的配置文件加进场景站在右手边。「载入配置…」照旧只换当前角色。
- **导出整个场景**：每个角色照导出精度在 `bakeFigure` 里重算一遍，GLB 用 `src/io/mergeGlb.ts` 把每个角色各自的 GLB 合成一个（每个角色一个父节点，带位置、朝向；网格、材质、贴图、骨架照搬，下标往后挪），带骨骼的每个角色一副骨架；OBJ、STL 把每块形状照摆放搬过去写在一起。文件名 `oc_scene*.glb/obj/stl`。在「造型」页里导出整个场景，摆过姿势的也是摆好的样子（和导出当前角色「看到什么导出什么」不一样）。
- 「显示成人部件」关着时，别人照样藏起来（设定里留着），拨开关会重算别人。
- 后台算别人时，当前角色用到的成品角色文件不会被挤出缓存（`keepCharacters`，缓存照旧最多 3 个）。
- 监控接口的快照里多了 `scene`（几个角色、各站在哪、哪个还在算），`agent.mjs notes latest` 也会带上；`notes replay` 只摆当前那一个。
- 新手引导在「导出」前面加了一步「好几个角色」。
- 测试：`tests/scene.test.ts`（场景数据、相对位置、存读）、`tests/mergeGlb.test.ts`（合 GLB、多副骨架、署名）、`tests/sceneBake.test.ts`（分部件的照设定算、摆姿势、带骨骼）。融合的、成品角色的在 5182 端口的页面里试过（两个、三个角色，摆姿势、转向、切换、删、恢复、刷新以后还在，整个场景合成的 GLB 两个父节点、带骨骼的两副骨架）。

没做：角色之间的互动（拉手、跨角色穿模检查、双人姿势）；问题单 replay 整个场景。

打包：exe、apk 照这个分支在 worktree 的 `release/` 里打了（版本号还是 2.7.4，没发布；apk 用的是主目录 `tools/android/sign.keystore` 那把钥匙，能盖在手机上装着的旧版上）。打包好的网页在静态服务器上试过：复制、切换、存档都正常，没有报错。
